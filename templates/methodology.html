Methodology and limitations

Every upload goes through the same six steps. Each step reports what it found and how reliable it is; no step is allowed to fill in for another when it fails.

1. Validation and storage

The extension must be an allowed image type, the file must be within the size limit, and Pillow must be able to fully decode it (a decompression-bomb pixel limit applies). Accepted files are saved under a random internal name derived from the report ID. Uploaded content is never executed.

2. SHA-256 fingerprint

The SHA-256 hash is computed over the exact bytes received, before any processing. The stored copy is re-hashed after writing and again whenever the detailed report is opened. Identical hashes across reports mean byte-identical files.

Custody note. {{ custody_note }}

3. Metadata extraction

Image properties, EXIF (IFD0, Exif sub-IFD, GPS), PNG/WEBP text chunks, ICC profile and the presence of XMP, IPTC and C2PA markers are read. Missing metadata is reported as missing information, not as evidence of manipulation.

4. AI-generated-image classifier

Model: {{ model_status.model_id }} at revision {{ model_status.revision }} (SigLIP image classifier, Apache-2.0, labels ai and hum). It is loaded once per server process. The image has EXIF orientation applied, transparency flattened onto white, and is resized to 224×224 by the model's own preprocessor.

6. Evidence consistency analysis

Readable rules compare the classifier result with metadata (camera tags, generator signatures, editing software, timestamps), file properties and file identity. Agreements and conflicts are both reported, with follow-up checks. The preliminary assessment is a qualitative label (e.g. "Further review recommended"), never an authenticity probability.
