Methodology

A preliminary, explainable assessment. No step can prove an image is real or fake.

How this works

1 · Validation and storage

Allowed extension, size limit, full decode by Pillow and a pixel limit. Files are stored under a random name and never executed.

2 · SHA-256 fingerprint

Computed over the exact bytes received, then re-checked on the stored copy each time the report opens.

3 · Metadata

EXIF, GPS, PNG/WEBP text chunks, ICC, and XMP/IPTC/C2PA markers. Missing metadata is reported as missing, not as manipulation.

5 · Heuristic caution score

6 · Consistency analysis

Readable rules compare the classifier with metadata, file properties and file identity. Agreements and conflicts are both shown, with follow-up checks. The result is a qualitative label, never an authenticity percentage.

7 · Report integrity (tamper-evident)

The PDF report is generated once, stored, and its SHA-256 is computed from the stored file and recorded in an audit log together with the original image's SHA-256. Every download re-checks the hash and is refused on mismatch. You can re-check the stored PDF or a copy you hold on the report page.

Tamper-evident, not tamper-proof. Changes are detected only while the recorded hash is intact: someone who can also edit the database could change both. A file cannot contain its own hash, so it is shown on the report page and in the TXT/JSON exports. This is not a legal chain of custody.
